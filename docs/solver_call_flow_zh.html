求解器调用流程

本文说明一次仿真请求从命令行进入、到 Rust 数值核心返回结果之间经过的各层组件。

文档类型：架构说明，面向需要修改或排查求解器的开发者。
覆盖范围：circuitopt/（Python）与 rust/crates/co-*（Rust）的调用关系。
不覆盖：各分析的数值算法推导、JSON 字段清单、CLI 参数全集，分别见 docs/module_overview_zh.md、docs/json_circuit_format_zh.md、docs/cli_reference_zh.md。

1 概述

求解器栈分为两侧。Python 侧负责描述与编排：读取 JSON 电路、确定要运行哪些分析、把电路结构翻译成矩阵索引、构造器件模型、最后把结果整理成指标和判据。Rust 侧负责数值计算：矩阵装配、Newton 迭代、时域积分、频域求解。

两侧只有一个接口，即 PyO3 扩展模块 circuitopt_core。Python 在这个接口上一次性提交一个完整的问题（例如「这条网表、这个时间网格、这些波形，求瞬态响应」），Rust 算完后一次性返回结果数组。Rust 在计算过程中不回调 Python，因此整段计算可以在释放 GIL 的状态下运行。

这一约束决定了 Python 侧的形态：所有需要逐步迭代的工作都必须提前折叠成静态数据。波形被采样成数组而不是保留为函数，器件参数被展开成数值卡片而不是保留为对象，节点名被替换成矩阵行号。因此调用链看起来层数较多，但每一层做的都是一次性的转换，而不是嵌套的循环。

3 术语

术语含义
MNA改进节点分析法。电路方程的标准形式：未知量是节点电压加若干支路电流。
stamp（印记）把一个元件的贡献加到 MNA 矩阵的特定位置上。
端子（term）元件的一个连接点。在编译后的电路描述中，端子有三种形式：待解节点（用行号引用）、波形输入（用输入槽位引用）、常数电压（直接带值）。
handle一个 BSIM4 器件在 Rust 侧的句柄，持有全部模型参数与器件内部状态。
corner（工艺角）本项目有两套互不相同的机制：硅工艺使用离散角名（tt/ss/ff/sf/fs），OTFT 使用连续参数偏移（typical/slow/fast）。
case / point批量运行的两个维度。case 指一个测试台，point 指一组 PVT 条件（角、温度、电源电压）。

4 入口

共有四个入口，最终都汇入同一个函数 analysis_dispatch.run_analysis_suite()，区别只在于调用它的次数与参数来源。

入口实现说明
命令行circuitopt/__main__.py主要入口，circuit-opt <子命令>，共 13 个子命令
Python APIcircuitopt 包测试与脚本直接调用 ac_solve、transient 等函数
HTTP 服务circuitopt/service/circuit-opt serve，提供任务队列与结果序列化
MCP 服务circuitopt/mcp/circuit-opt mcp，供 agent 调用的工具接口

子命令分类

按对求解器的调用次数，13 个子命令分为三类。

单次运行。run 按 JSON 的 analyses 块运行一套分析；chopper 运行斩波专用分析链；adc 解码 ADC 波形并计算静态与动态指标；plot 只读取已有结果作图。

批量运行。signoff 在 PVT 网格上运行多个测试台；explore 做设计空间搜索与 Pareto 筛选；corners 做工艺角扫描；mc 做失配蒙特卡洛；dataset 生成代理模型训练集。

辅助工具。verify-engine 在两个引擎上运行同一个用例并比对；passive-bom 统计无源元件与估算面积；serve 与 mcp 启动服务。

引擎开关

--engine 选项与 CIRCUIT_ENGINE 环境变量仍然存在，但取值只有 rust 一个。传入 python 或 numba 会报错退出——这两个引擎已在 v2.0.0 移除，保留错误提示是为了避免旧脚本静默改变行为。开关在 circuitopt/__init__.py 顶部、任何求解器被导入之前解析一次，实现在 _engine.apply_engine_env()。

5 电路描述

这一层把 JSON 文本转换成矩阵索引。涉及四个对象，职责如下。

对象实现职责
CircuitSpeccircuit_loader.py JSON 文件内容的不可变表示：尺寸、偏置、拓扑、待运行的分析、signoff 判据。
Topologytopology.py 电路结构：哪些节点待求解、哪些是固定电压轨、每个晶体管的漏栅源接在何处、有哪些直流初值猜测。
CompiledTopologycompiled_topology.py 矩阵层面的描述：节点名到行列号的映射、每个无源元件与受控源的印记位置、波形名到输入槽位的映射。
CircuitBindingdevice_factory.py 模型绑定：topo、model_types、device_kwargs、nf 与默认直流种子的集合。

CircuitBinding 的作用

run_analysis_suite 会连续调用六个求解器，每个都需要相同的五项模型信息。早期实现逐个传递这些参数，遗漏其中一项时求解器会退回默认的 OTFT 模型——不报错，但结果对应的是另一个器件。CircuitBinding 把这五项打包成一个对象，由 spec.binding().at_corner(corner) 一次构造，六个分析共用同一份。

6 分析调度

analysis_dispatch.run_analysis_suite() 是全项目唯一编排「一个电路运行一整套分析」的函数。它承担四项职责。

配置校验。在任何求解器运行之前校验配置，未知的配置键按硬错误处理。JSON 是唯一入口，一个拼错的选项若被忽略，分析会用默认值运行完成，结果看起来正常但对应的不是所请求的配置。实现在 analysis_options.validate_analysis_cfg()。

顺序执行。按 ANALYSIS_ORDER = (ac, noise, transient, pss, pac, pnoise) 运行。顺序有依赖含义：噪声分析需要复用交流分析已解出的直流工作点。

依赖补齐。只请求 pac 或 pnoise 时，调度层会先运行 pss。同时校验工艺角一致性：若已有的 PSS 结果与依赖分析请求的角不同，报错而非沿用。

结果复用。噪声分析若与交流分析处于同一工艺角、同一频率网格，直接复用后者的结果，省去一次直流求解与一次线性化。

波形的处理

JSON 的 periodic 块支持 constant、sine、square、pulse、pwl 五种波形。build_periodic_context() 在这一层把它们按时间网格采样成 numpy 数组再向下传递；Rust 侧只接收「时间点数组加每个输入一行采样值」，不理解波形类型。

采样数组是分段线性的，因此方波的跳变若不落在采样点上，自适应步进器无法察觉。_with_adaptive_waveform_breakpoints() 负责把每个方波与脉冲的边沿时刻插入时间网格。两点实现细节：

  • 瞬态分析不补齐整周期（close_period=False）。MDAC 测试台只运行 10 ns 周期中的 5 ns，补齐会使求解窗口翻倍，并返回超出 tstop 的网格。
  • 落在容差内的重复时刻需要合并。否则会留下长度接近浮点精度极限的退化区间，使步长策略中的斜率归一化失效。

7 器件模型

模型注册表

device_model.py 维护一张扁平注册表，键为 "<pdk>.<polarity>"，例如 "tsmc28hpcp.nmos"。新增一个 PDK 需要写一个 TransistorModel 子类并调用一次 register_pdk()，不需要修改求解器代码。求解器通过类属性（如 HAS_TERMINAL_LINEARIZATION、TRANSIENT_BACKEND）按能力分派，而不是按具体后端类型判断。

同一个工艺可能注册两组类：tsmc28hpcp 对应原生引擎，tsmc28hpcp_ngspice 对应厂商 deck 适配器，且后者只在 circuitopt.tsmc28_model 被导入后才注册。网表绑错名字时的表现是 ngspice 路径报「mixed FreePDK45/other-model ngspice analysis is not supported」。

器件构造

device_factory.build_devices() 是唯一的器件构造入口。输入尺寸、指数、并联数、工艺角、模型类型与构造参数，输出 {名字: 模型实例}。三个几何参数的区别如下。

参数含义影响
W / L单指宽度与沟道长度电流、跨导、输出电导
NF把一个器件的宽度切分成几指不改变总电流，改变栅电容，因而影响带宽和电容相关的噪声
M并联的相同器件个数电流、电容、噪声功率均按 M 缩放，等价于 ngspice 的 m=

硅工艺的卡片来源

厂商模型库（本地文件，不进入仓库，也不落盘缓存）经词法分析、Pratt 解析与表达式求值后，按工艺角选择 section、按几何选择 bin，展开成一张扁平的数值 BSIM4.5 卡片。卡片由 Bsim4CardCache 缓存，缓存键包含模型文件的路径、修改时间与大小，以及工艺角、温度和几何 bin；缓存仅存在于进程内。

Python 侧的解析实现在 circuitopt/spice/，Rust 侧的等价实现在 co-spice 与 co-pdk，后者是前者的一对一移植。

直流求解的退避顺序

直流是最容易不收敛的一步，因此有一条三级退避链，实现在 ac_solver.ac_solve()。

  1. 调用方显式提供的初值优先使用，且不保留后备猜测。蒙特卡洛与角点扫描会把上一个已求解的工作点带入，这类初值是权威的；若探测特定工作分支的初值失败，应当报失败而不是退回标称解。
  2. 全 BSIM 电路使用编译 Newton（solve_dc()），逐个尝试已声明的初值猜测。收敛后仍用 Python 侧的残差函数复核一遍才接受。
  3. 依次退回 scipy fsolve 与 bounded_least_squares_dc。

AFE 拓扑另有一套对称种子与源斜坡延拓的启发式，位于 dc_solver.py。它针对该拓扑的多稳态特性设计，刻意不合并进通用求解路径。

9 Python 与 Rust 的边界

全项目只有一处语言边界，由 rust/crates/co-py 提供（PyO3，abi3-py310），编译产物是扩展模块 circuitopt_core。导出内容分三类。

问题对象：LtiProblem、Bsim4TransientProblem、OtftTransientProblem、PeriodicLinearizationProblem、CompiledCampaign、PreparedCampaign、CompiledSarConversion。均为构造一次、多次求解。

器件与工艺：Bsim4Device（另附一套 C ABI 供 native.py 的 ctypes 路径使用）、OtftModel、CompiledPdk，以及 spice_* 系列解析函数。

零散函数：engine_info()、integration_rows()、dense_neg_solve()、mna_term_values()、serial_device_eval()。

问题描述的格式

序列化桥（_rust_*.py）的产物不含任何 Python 对象，只有嵌套的元组与浮点数：

# _rust_lti.build_lti_problem() 产出的一部分
spec = {
  "size": 12,                                    # 矩阵阶数：节点数加支路数
  "mos_devices": [ (drain, gate, source, gm, gds, Cgs, Cgd), ... ],
  "capacitors":  [ (a, b, 5.0e-13), ... ],
  "resistors":   [ (a, b, 1.25e-5), ... ],       # 存电导，非电阻
  "voltage_sources": [ (p, q, branch, emf_re, emf_im), ... ],
}
# 其中 a / b / drain 等每个端子都是 (kind, reference, value) 三元组
circuitopt_core.LtiProblem(spec)

频域结果以实部虚部对的形式返回，Python 侧由 complex_array() 重组为 numpy 复数数组。原因是 PyO3 的复数 ABI 不稳定。

11 批量执行

批量运行有两条路径，选择依据是每个点是否需要运行一整套分析并施加判据。

路径一：signoff campaign

用于 circuit-opt signoff。并行发生在 PVT 点这一级，每个点内部串行运行全部测试台。

signoff_campaign.run_signoff_campaign(path, workers=N)
├─ load_campaign_json()          读 manifest 并校验
├─ _load_case_bases()            读入各测试台 deck
├─ 预检：每个工艺角先 prepare 一次并校验 signoff 配置
│                                结构性错误属于配置失败，应一次报出，
│                                而不是变成 45 行重复的 invalid
└─ _run_prepared_campaign()
   └─ ThreadPoolExecutor(N) 分发 PVT 点
      └─ _run_point_worker()
         ├─ with worker_device_eval(N)          见 §13
         └─ with isolated_native_device_cache() 见下
            └─ for case in cases:
               prepare_case_dict()  →  circuit_from_dict()
               run_analysis_suite(spec)          §6
               evaluate_signoff(spec, results)   run_contract.py

isolated_native_device_cache() 是正确性所需，而非性能优化。BSIM handle 在调用之间保留热启动与限幅状态；共享同一张卡片的两个点（同角同温、不同电源电压）会租用同一个 handle，从而看到对方的状态。其表现是 campaign 只在 workers=1 时可复现。把租用隔离到每个点各自的命名空间后，任意 worker 数下每个点的结果都只取决于该点自身。

路径二：compiled campaign

用于 explore、corners、mc、dataset，即「同一个电路、更换一批尺寸、只需少量标量指标」的批量。调用链为 _campaign_sweep.py → _rust_campaign.py → CompiledCampaign。特点：

  • 器件构造、直流、交流、噪声整条流水线都在 Rust 内完成，无逐候选的 Python 回调，整批共用一次 GIL 释放。
  • 随机失配抽样与各候选的直流初值全部提前计算好，Rust 批次运行期间不回调 Python。
  • 并行轴二选一：候选数不小于 worker 数时按候选并行，否则按频点并行，保证单一线程池不被超额订阅。

并非所有电路都能走这条路径。硅 BSIM 的 5T OTA 是单稳的，编译 Newton 冷启动可以到达与冻结的 scipy 路径相同的物理分支（最差节点差约 2e-5 V）；AFE 的 OTFT 是多稳的，冷启动可能选到另一个分支。因此 _campaign_sweep.py 中带有一条按器件族区分的准入策略。

SAR 与 ADC

sar.py  run_sar_conversion()      冻结的 Python 参考实现，同时作为回退路径
  └─ sar_rust.build_sar_batch()   不支持的拓扑抛 SarRustUnavailable
     └─ circuitopt_core.CompiledSarConversion
        └─ co_core::sar           逐位续算，整条转换一次 GIL 释放
adc.py                            由码流计算 INL / DNL / SNDR / ENOB

「逐位续算」指每一位在前一位的状态上继续求解，而不是每位重放整条波形；后者会使一次 N 位转换的成本变成 N 的平方量级。

verify-engine

circuit-opt verify-engine campaign.json --case residue_max --point ss/125/0.85

engine_crosscheck.py 做三件事。

在内存中改写模型绑定（oracle_deck()）。提交的网表保持引擎中立，运行前才把 pdk 改写为 *_ngspice。若改由维护两份网表实现，两份迟早会不一致。

排除受激励驱动的节点（driven_nodes()）。这些节点在两个引擎中按定义相同，比较它们等于比较测试台本身；且一个 20 ps 的时钟边沿落在两套不同的步长网格上时，其偏差会超过所有真实节点，占据比较结果的首位。

判定依据取稳态偏差而非峰值偏差。快速跳变处的大偏差来自步长落点差异，稳定后仍不收敛的偏差才表示两个引擎不一致。峰值偏差仍然报告，但使用独立的、更宽的阈值单独标记。

13 并行策略

原则：拥有外层循环的一方拥有并行，内层改为串行执行。

编译核心通过一个进程级线程池评估瞬态的器件批次。对单次孤立求解这是合理的；但 signoff 的 PVT 点、SAR 的转换序列、蒙特卡洛试验都向同一个池提交任务，外层 worker 会互相排队。_parallel.worker_device_eval(workers) 返回一个上下文管理器，使调用线程的器件批次改为内联求值。只有调度方式改变，结果逐位相同。

参考机上 16 个 TSMC28 MDAC 残差瞬态的实测：

调度方式1 线程8 线程8 线程时核占用
内层使用共享池4.90 s4.03 s7.8 核，但外层 worker 均在排队
内层内联10.54 s3.19 s6.0 核

两种情况下不做让路：workers ≤ 1 时没有外层并行需要保护，线程池能让单次求解更快；外层任务数小于 worker 数时外层无法占满机器，空闲核心交给线程池更合适。

这条原则的适用范围是 Python 侧的 BSIM 池路径。编译 SAR 内核相反：外层串行，内核使用 Rayon。参考机只有 4 个性能核，worker 数超过该值后收益迅速趋平。

GIL 的位置

py.detach() 位于 co-py 的每个求解入口。计算密集部分本就不持有 GIL，因此改用 Python 3.14 的自由线程构建不会加速这些路径。Python 侧剩余的单线程工作是问题描述装配与结果整理，两者都不是热点。

其中 solve_bsim4_dc_rust() 一步值得注意。瞬态的起点必须在与瞬态起始时刻完全相同的源配置下求解，即每个由波形驱动的电压源都要钳位在其 u(t₀) 采样值上。早期实现在直流编译时把这类源一律取 0 V，于是 t₀⁺ 的第一步把整个源摆幅经耦合电容注入高阻网络。在 MDAC 保持相测试台上，两个 CDAC 底极板从 0 跳变到 VCM，向浮空虚地注入约 1.17 pC/边，输出共模在 5 ns 内上升 0.42 V 并撞轨，表现为两套不同拓扑在全部 45 个 PVT 点的瞬态全部失败，而 golden 语料始终逐位通过。修正方式是 CompiledTopology(..., dc_input_values=...)，实现在 compiled_topology.py。

15 约束与注意事项

以下六项是修改求解器时容易违反的约束，均有对应的测试或实测数据支撑。

器件状态跨调用保留。BSIM 的求值是路径相关的，热启动与限幅状态会在调用之间保留。两个推论：回滚重解时必须调用 resync_evaluator；并行 campaign 必须隔离 handle 租用（见 §11）。

BSIM 后端的锁必须保持粗粒度。收窄锁范围看似是明显的优化，实测慢 35% 至 45%。该锁真正串行化的是 vendored C 中线程不安全的 setup 路径，而非计算本身。

自适应重启不使用盲步。在断点处重启积分历史时，早期实现走一个盲步。改为 Richardson 双半步后误差下降约 40 倍，步数增加约 35%。reltol 与 max_step 对这一环节无效，它使用独立的误差预算。

采样系统的共模判据定义在时刻上而非窗口上。要求整个窗口内共模都满足限值对采样系统过严，压摆阶段本就会偏离。正确的判据是 checkpoint_error，只在命名的时刻（静态工作点、保持相末尾）检查。实现在 run_contract._checkpoint_error_measurement()。

对生成器源码做文本替换时必须断言目标存在。str.replace() 在目标字符串不存在时不报错，只是不做任何修改。此处曾因此连续三轮测量的都是未修改的设计。同理，git checkout <file> 会静默丢弃未提交的修改。

未知配置键按错误处理。理由见 §6 的配置校验。
